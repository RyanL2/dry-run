# C-0009 · full-tree fingerprint walks dominate fixed cost · track: sandbox-perf · method: M-fixed-cost · status: supported
Observation: C-0003 found fixed stages make up 87% of the 566 ms added latency on a 20k-file repo (prepare 211 ms, post-run 270 ms).
Hypothesis: The two full-tree lstat walks (before, and after for lower_changed) plus the upper extraction make up most of the fixed cost.
Change: Per-sub-stage timers (fingerprint pre/post, tmp snapshot, git snapshot, extract, git effects) over the C-0003 command set; shared run with C-0010 and C-0011.
Prediction: The two fingerprint walks together take ≥ 40% of fixed cost. Replacing the post-run walk with a check on changed dirs only (dir mtimes) cuts ≥ 100 ms.
Disproof: The fingerprint walks take < 20% of fixed cost.
Budget: 30 min CPU (the instrumented run is shared).
Verdict: supported (ledger 2026-10-16 "stages", card C-0009..C-0011, row with 1 file under /tmp). Median fixed cost 513.5 ms; the two walks are 75% of it (median per command): fp_pre 151 ms, fp_post 233.5 ms (the post walk also digests both trees). Prediction part 1 (>= 40%) holds. Part 2 (dir-mtime post check saves >= 100 ms) is untested: dir mtimes miss in-place edits of existing files, so lower_changed would lose concurrent modifications. That trade-off needs a decision before it is built.
