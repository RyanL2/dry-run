# C-0010 · sandboxed git queries dominate fixed cost · track: sandbox-perf · method: M-fixed-cost · status: abandoned
Observation: C-0003 found fixed stages make up 87% of the 566 ms added latency on a 20k-file git repo.
Hypothesis: Each read-only bwrap launch plus git status/ls-files/ls-tree over 20k entries (and objects_exist / merge-base later) costs more than the filesystem walks.
Change: The same instrumented run as C-0009. If supported, run the git snapshot lazily: only when the ChangeSet deletes or modifies tracked paths or touches .git.
Prediction: Git queries take ≥ 40% of fixed cost. The lazy snapshot saves ≥ 150 ms on commands that only create files.
Disproof: Git queries take < 20% of fixed cost.
Budget: shared with C-0009.
Verdict: refuted, abandoned (ledger 2026-10-16 "stages", card C-0009..C-0011). Git work (snapshot 83.5 ms + annotate 2 ms + git_effects 0 ms) is 17% of the 513.5 ms median fixed cost, and 14% with a populated /tmp, which is under the 20% Disproof bound. The lazy git snapshot is not built. Revive only if: git work exceeds 20% of fixed cost, e.g. after the C-0009 walks are made cheaper.
Follow-up (2026-10-16, feat/fingerprint-speedup): the git snapshot now runs next to the shadow run, between the two walks, and median judge.git_wait is 0 ms, so it is off the fixed-cost path. The lazy snapshot is still not needed.
